## 先选内核还是图形客户端

Mihomo 是处理规则、代理协议和网络流量的内核，适合命令行、路由器或被其他应用调用；Clash Verge Rev 是桌面图形客户端，提供配置管理、系统代理、订阅更新和日志界面。两者都可能被用户简称为 Clash，但下载文件、更新方式和适用系统不同。

只想在 Windows、macOS 或 Linux 桌面管理现有合法配置的用户，通常更容易从图形客户端入手；需要在服务器、OpenWrt 或自动化环境中运行时，才直接选择内核。客户端不会因为安装完成就自动产生可用节点。

## 为什么只认官方 Releases

代码托管页面仍可能被仿冒，因此要核对项目维护者、安装文档与 Releases 是否互相链接。真正下载前再看项目是否被归档、最新发布由谁签发、资产列表是否符合文档。

聚合站可能重新打包、插入广告、滞后更新或改变签名；网盘文件则缺少可追溯发布记录。即使文件名完全相同，也不能证明字节内容相同。

## Windows、macOS 与 Linux 怎么选文件

Windows 先判断 x64、ARM64 或旧的 32 位环境，再区分安装包和便携包。macOS 需要区分 Apple Silicon 与 Intel；系统可能阻止未满足签名或隔离要求的程序，不应通过关闭全部安全保护来强行运行。Linux 则要区分发行版包格式、CPU 架构和桌面环境。

文件名不确定时，先读同一版本的 release notes 与安装文档。不要凭下载量选择一个“看起来最大”的文件，也不要安装与系统架构不匹配的包。

## 下载后做四项校验

第一，确认浏览器地址栏仍是 github.com 下的官方仓库；第二，保存版本号、发布日期和资产文件名；第三，若发布页提供校验和或签名，计算本地文件并逐字符比对；第四，首次运行前查看系统签名、杀毒扫描与所需权限。
